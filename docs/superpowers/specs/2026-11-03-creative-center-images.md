# 创作中心图片生成替换方案

目标：移除 fal.ai PhotoMaker，复用 Hermes 创作中心的异步图片协议，默认使用 `gpt-image-2` 为参考人像生成妆容。

## 接口依据

参考本机 Hermes 的 `router-creative-image` skill 及其 `references/api.md`。通过 `https://api.router.team/api/public/creative-center` 接入，使用 `ROUTER_CREATIVE_API_KEY`。2026-11-03 已真实读取 `/config`，当前凭证支持 GPT 与 Grok 图片模型。可配置 `AI_IMAGE_MODEL=gpt-image-2` 或 `grok-imagine-image-2.0`，默认清晰度 `1k`；不自动更换模型。

## 数据流程

1. 为 R2 原图签名；读取创作中心配置，校验模型、清晰度、价格；保存提交前的历史编号和唯一提示词。
2. 保留人物五官、肤色、表情、姿势、发型、衣着和背景，仅编辑请求的妆容；每个任务生成一张图片。
3. 在 Inngest 独立持久化步骤中执行一次提交。返回任务编号后，后续步骤只查询该编号。
4. 提交响应不确定时，通过提交前历史快照、唯一提示词和模型恢复原任务；不重新提交。不确定或查询异常均不当作模型生成失败。
5. 使用 Inngest 的持久化等待查询完成或明确失败；成功后沿用现有结果上传和额度结算流程。价格从配置读取，用于预算预留；保留既有环境预算估算作为下限。

## 范围

新增创作中心客户端、妆容提示词与任务编排、独立单图验收脚本；移除 fal SDK、旧适配器和仅用于 ZIP 的依赖；更新配置与上线文档。保持现有网站交互、鉴权、原图存储、审核、作品和积分流程。

视频 skill 使用 Grok，但当前服务没有视频业务，本次不新增视频功能。模型侧单图验收使用仓库内 AI 虚拟人物；数据库、Supabase、R2、审核服务的完整联调仍需独立配置。

## 凭证与验证

本地只将 Hermes 已有的创作中心密钥配置到被 Git 忽略的 `.env.local`；代码、文档、提交、日志中均不包含值。生产部署通过环境配置同名变量，不读取 Hermes 本地目录。

先运行失败的行为测试，再实现适配器；验证任务恢复、模型配置、参考图输入、任务轮询、失败处理与价格预算。运行全量测试、lint、类型检查及构建检查。单图真实验收前保存提交记录，等待超时仅恢复原记录，不重发生成请求。

Inngest 的步骤记录用于应用内恢复，不构成供应商的原子幂等保证；进程在供应商接受请求与步骤保存之间中断时，需要依据保留的提交前快照核对历史，通过数据库原子提交意图标记阻止再次 POST，改为核对原任务。标记落库后、实际 POST 前进程中断时会保守停留在待核对状态，需要人工处理。每次调用最多轮询 60 次，然后通过新事件继续，避免步骤数超限。
